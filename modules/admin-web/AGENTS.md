# admin-web 模块协作约束

本文件在仓库根 `AGENTS.md` 之上叠加，**只加严，不放宽**。

## 1. 职责边界

- 拥有：管理端 UI、模块健康面板、图查询/人格/审计/巩固/提案的只读或审批界面。
- 不拥有：任何业务数据；只调用各后端模块的版本化能力。
- 禁止在前端直连数据库、构造原始 Cypher、或绕过目标模块的服务端鉴权。

## 2. 不可破坏的规则

1. **前端不是授权边界**：菜单与按钮可见性不构成授权；每个写/审批操作仍由目标模块校验权限。
2. **管理端最小权限**：只读页面不调用写能力；审批动作单独授权并留审计。
3. **不缓存敏感数据**：不在浏览器持久化人格叙事、记忆原文、提案详情、凭据。
4. **健康探测受控**：上游地址来自受控配置（`UPSTREAMS`），禁止把用户输入当探测目标（SSRF）。
5. **不伪造数据**：没有后端实现时显示“仅声明/不可达”，不得用样例数据冒充真实状态。
6. **错误可见**：显示稳定错误码与请求 ID，不显示堆栈或内部地址。

## 3. 最小 Demo 状态

- 已实现：管理壳、菜单权限过滤、上游健康探测、**模型设置**（读取/保存 LLM 配置，密钥只写不读）。
- 已实现：**身份层编辑器**（读取 + 保存为新版本）、**适应层编辑器**（读取 + 有界调整）、
  **提案审批**（列表 + 批准/拒绝）。三者经 Node sidecar 以同源 `/api/persona-state/*` 代理到
  persona-state，浏览器不直连 8083；写操作由 persona-state 服务端鉴权。
- 身份层保存、提案批准均需二次确认；前端不会自行截断超限 delta 或漂移，按服务端 409/422 原样显示稳定错误码。
- 未实现：记忆图、检索审计、巩固监控页面仍为占位；**回滚入口**尚无 UI（能力已实现）。
- 前端测试与构建可运行；浏览器端到端未验证。

## 4. 命令

```bash
cd modules/admin-web/web
npm install
npm test
npm run build
npm start                 # 4173：/conversation/ 与 /admin/（同源）
```

## 5. 评审关注点

- 健康探测是否只允许配置内的地址？超时是否受控？
- 审批操作是否有二次确认与审计？
- 图查询是否只发送结构化参数，而非 Cypher 字符串？
- 菜单与 `contracts/menu.yaml` 是否一致？
